# 기획 하네스 오케스트레이터

문제 정의 1개를 받아 9단계를 순서대로 자동 실행한다. **유일한 수동 개입은 Step 7(아이디어 선택)** 뿐이다.

## 진행 전 준비

1. 사용자 입력에서 **문제 정의 1문장**을 확보한다. 없으면 한 번만 묻는다.
   형식: `[누구]가 [어떤 상황]에서 [무엇]을 하려 하지만 [무엇] 때문에 [어떤 불편]을 겪는다.`
2. **slug 생성**: 문제에서 핵심 키워드 2~3개를 뽑아 `소문자-하이픈` 형식으로 만든다. 한글 키워드는 그대로 쓰되 공백은 하이픈으로. (예: `가계부-직장인`)
3. **출력 디렉터리**: `planning-output/YYYYMMDD-[slug]/` (날짜는 오늘). 첫 Write 시 자동 생성된다.
4. TodoWrite로 Step 2~9를 할 일로 등록하고 진행하며 갱신한다.

## 실행 순서

각 단계는 해당 단계 스킬의 규칙을 그대로 따른다. 단계 스킬을 `Skill` 도구로 호출하거나, 규칙을 알고 있으면 직접 수행하되 **출력 파일 경로와 형식은 반드시 아래대로** 한다.

### Step 2 — 페르소나 (역할: 서비스 디자이너 10년차)

`planning-persona` 규칙으로 페르소나 3개 작성 → `01-personas.md` 저장.

### Step 3 — Journey Map (역할: 서비스 디자이너 10년차)

`planning-journey-map` 규칙으로 페르소나별 5단계 여정 표 작성 → `02-journey-maps.md` 저장.
**감정 1~2점 행에 `⚠️ MVP` 표시** — 이 행만 다음 단계 HMW의 근거가 된다.

### Step 4 — HMW + 아이디어 12개 (역할: 창업 5회 경험의 제품 기획자)

`planning-hmw` 규칙으로 HMW 6개 + 아이디어 12개 표 작성 → `03-hmw-ideas.md` 저장.
제약: 예산 1천만 원 이하 / 3주 MVP / AI 핵심 기능 필수. 법적 문제·기능적 외부 요인 검토 후 제외.

### Step 5·6 — AARRR + Aha 가설 (병렬, 핵심 단계)

12개 아이디어 전체에 대해 AARRR 가설 + Aha Moment 가설을 **병렬로** 산출한다.

**병렬 dispatch 방법**:

- 12개 아이디어를 **3개씩 4배치**로 나눈다.
- `Agent` 도구로 `planning-idea-brief` 에이전트를 **4개 동시에**(한 메시지에서 4번 호출) dispatch한다.
- 각 dispatch 프롬프트에 포함: 문제 정의, 담당 아이디어 3개(번호·서비스명·설명·타깃·차별점·리스크), 관련 페르소나 요약.
- 4개 에이전트 결과를 번호 순서대로 취합하여 `04-idea-brief.md` 한 파일로 저장한다.
  - 파일 맨 위에 12개 아이디어 한눈에 보기 요약 표(번호/서비스명/NSM 한 줄/Aha 한 줄)를 만들고, 그 아래 각 아이디어 상세 블록을 붙인다.

> superpowers:dispatching-parallel-agents 스킬 원칙을 따른다 — 독립적이고 상태 공유가 없으므로 병렬에 적합하다.

### Step 7 — 사용자 아이디어 선택 (유일한 수동 개입)

`04-idea-brief.md`의 요약 표를 사용자에게 마크다운 표로 보여주고, **`AskUserQuestion` 도구로 선택을 받는다** (복수 선택 가능하도록 multiSelect 고려, 또는 "여러 개 선택 가능"임을 명시).

복수 선택 시 각 아이디어를 별도 PRD로 처리한다.

#### 아이디어 미선택 시 — 재생성 플로우 (최대 2회)

사용자가 선택하지 않거나 "다시", "새 아이디어", "마음에 드는 게 없어요" 등을 입력하면 아래 플로우를 실행한다. **재생성은 최대 2회까지만 허용**한다.

**① 방향 질문 (AskUserQuestion, 1회)**

```
질문: "어떤 방향으로 아이디어를 바꿀까요?"
옵션:
  A. 소셜·커뮤니티 강화 — 사람 간 연결·협업 중심으로
  B. 개인 집중 도구 중심 — 혼자 쓰는 AI 생산성 도구로
  C. 공간·환경 중심 — 물리적 작업 공간 문제 해결로
  D. 완전히 다른 각도 (Other로 자유 입력)
```

**② 아이디어 재생성**

- 사용자 방향을 HMW 각도·제약에 반영하여 `planning-hmw` 규칙으로 HMW 6개 + 아이디어 12개 재생성.
- 파일은 버전 suffix를 붙여 저장 (1차 재생성: `03-hmw-ideas-v2.md`, `04-idea-brief-v2.md` / 2차: `v3`). 원본 파일은 덮어쓰지 않는다.
- Step 5·6과 동일하게 `planning-idea-brief` 에이전트 4개 병렬 dispatch → 취합 후 저장.

**③ 새 요약 표 제시 + 재선택 요청**

새 아이디어 요약 표를 마크다운으로 보여주고 다시 `AskUserQuestion`으로 선택을 받는다.

**④ 2회 재생성 후에도 선택 없을 경우 — 강제 추천**

지금까지 생성된 전체 아이디어 중 **바이럴 K값과 D7 리텐션이 가장 높은 아이디어 1개**를 선정해 추천한다.

```
"[서비스명]이 지표상 가장 강합니다 (K: X, D7: Y%).
이 아이디어로 PRD를 진행할까요?"
```

`AskUserQuestion`으로 Yes / No (다시 처음부터) 중 선택받는다.

- Yes → Step 8 진행
- No → Step 2부터 문제 정의를 다시 받아 전체 재실행

### Step 8·9 — PRD (역할: SaaS PM 10년차)

`planning-prd` 규칙으로 선택된 아이디어에 대해 1-Pager PRD + PRD 초안 작성 → `05-prd.md` 저장.
규칙: 성공 기준 숫자 필수 / Out of Scope 3개 이상 / 열린 질문 3개 / 불확실도 ★~★★★ 섹션별 표시.

### 최종 — 합본

`01`~`05` 내용을 순서대로 합쳐 `[slug]-기획결과-전체.md` 저장.

## 출력 파일 구조

```
planning-output/YYYYMMDD-[slug]/
├── 01-personas.md
├── 02-journey-maps.md
├── 03-hmw-ideas.md             # 1차 아이디어 12개
├── 03-hmw-ideas-v2.md          # (재생성 1차 시 생성)
├── 03-hmw-ideas-v3.md          # (재생성 2차 시 생성)
├── 04-idea-brief.md            # 1차 AARRR + Aha 가설 (병렬 산출 취합)
├── 04-idea-brief-v2.md         # (재생성 1차 시 생성)
├── 04-idea-brief-v3.md         # (재생성 2차 시 생성)
├── 05-prd.md                   # 선택된 아이디어 1-Pager + PRD 초안
└── [slug]-기획결과-전체.md
```

> v2·v3 파일은 Step 7 미선택 재생성 시에만 생성된다. 원본(`03-hmw-ideas.md`, `04-idea-brief.md`)은 항상 보존한다.
