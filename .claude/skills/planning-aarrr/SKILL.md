# Step 5 — AARRR 지표 가설

**역할: "스타트업 그로스 해커 8년차"**

> 하네스 전체 실행 중 12개 아이디어를 병렬 처리할 때는 `planning-idea-brief` 에이전트가 이 규칙을 적용한다. 이 스킬은 **단독/특정 아이디어 실행**용이다.

## 입력

선택된 아이디어(서비스명·타깃·차별점). 없으면 `03-hmw-ideas.md`에서 가져오거나 사용자에게 받는다.

## 작업

### 1) North Star Metric 1문장

> `[서비스명]은(는) [사용자]가 [기간 단위]에 [핵심 행동]을 몇 번 하는지로 성공을 잰다.`

예: "레시피봇은 1인가구 사용자가 일주일에 냉장고 재료로 완성한 요리 개수로 성공을 잰다."

### 2) AARRR 5개 지표 표

**표 컬럼**: 단계 / 가설·목표값 / 측정 방법 / 참고 사례

| 단계                | 내용                |
| ------------------- | ------------------- |
| Acquisition (유입)  | 어느 채널로 몇 명   |
| Activation (활성화) | 어떤 행동 후 Aha    |
| Retention (유지)    | D7 목표 %           |
| Revenue (수익)      | ARPU 또는 가격 모델 |
| Referral (추천)     | 초대 동기와 예상 K  |

### 불확실성 처리

수치를 모르거나 확신이 없으면 **비워두지 말고** 유사 서비스 초기 실적을 근거로 범위(예: "D7 15~25%")로 제시한다. 정확한 수치보다 방향 설정이 먼저다.

## 출력

NSM 문장 + AARRR 표.

**파일 저장**: 하네스 단독 단계 실행이면 `planning-output/YYYYMMDD-[slug]/04-idea-brief.md`에 해당 아이디어 블록으로 반영. 독립 실행이면 보여주고 저장 여부를 묻는다.
